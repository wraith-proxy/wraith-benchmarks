4. **The rollout (lines 49-51) is destructive and has no rollback.**
   - `TRUNCATE` runs before the replacement is proven, so a failed `INSERT SELECT` leaves an empty table.
   - There's no backfill range. `require_partition_filter` also means `INSERT ... SELECT ...` needs a `ds` filter, so a full history load needs a bounded loop or range.
   - "Check row counts" has no expected number or comparison.
   - Better approach: build into a dev or shadow table, compare, then swap or load by partition. Write the rollback down before any truncate.
5. **The MERGE isn't a safe snapshot load.**
   - It never deletes rows that vanish from a re-delivered `ds`, so reruns can leave stale rows.
   - The target's partitioning and clustering aren't stated, and the `ON` clause has no partition-pruning predicate beyond `d.ds = n.ds`.
   - Use a partition overwrite (delete then insert for the `ds`, or `insert_overwrite`) and state the partitioning.

  - The dataset is called `snap_private`, but the contract says `internal`. Pick one.

  - The primary key omits `ds`. It should be `ds, sku, warehouse_id`.
  - There is no schema, types, nullability, quality rules (non-null keys, `amount >= 0`?), freshness SLA or retention.
